# ShareDesk अपडेट

ShareDesk नया संस्करण इस तरह लागू करता है — इंस्टॉल के समय बनी **मेरी GitHub रिपॉज़िटरी** को अपडेट किया जाता है, और उस रिपॉज़िटरी से जुड़ा Vercel उसे दोबारा डिप्लॉय करता है। Google Drive की फ़ाइलें, उपयोगकर्ता, आमंत्रण और नोट तथा Vercel के एनवायरनमेंट वेरिएबल कोड अपडेट के दायरे में नहीं आते।

## अपडेट बटन का उपयोग

ShareDesk नया संस्करण अपने आप लागू नहीं करता। व्यवस्थापक के रूप में साइन इन करने पर यह नवीनतम स्थिर संस्करण की एक बार जाँच करता है, और नया संस्करण उपलब्ध होने पर ही टास्कबार के `अपडेट` पर तारा दिखाता है।

नीचे दी गई [वन-क्लिक अपडेट की तैयारी](#वन-क्लिक-अपडेट-की-तैयारी-एक-बार) एक बार पूरी कर चुके इंस्टॉल में GitHub पेज पर गए बिना ही ShareDesk के भीतर अपडेट पूरा हो जाता है।

1. तारे वाले `अपडेट` को दबाकर ShareDesk के भीतर वर्तमान संस्करण और नवीनतम स्थिर संस्करण देखें। तारा न हो तब भी बटन दबाकर स्वयं जाँच की जा सकती है।
2. नया संस्करण उपलब्ध हो तो भीतर की स्क्रीन पर `अभी अपडेट करें` दबाएँ।
3. ShareDesk आपकी ओर से इंस्टॉल रिपॉज़िटरी का अपडेट workflow चलाता है और उसी विंडो में प्रगति दिखाता है। `अपडेट लागू हो रहा है` → `नया संस्करण डिप्लॉय हो रहा है` से गुज़रकर पूरा होने पर `अपडेट पूरा हो गया`, और कोई समस्या हो तो `अपडेट विफल रहा` दिखाई देता है। इसमें कुछ मिनट लग सकते हैं।
4. सभी जाँचें पास होने पर इंस्टॉल रिपॉज़िटरी के `main` में अपडेट कमिट बनता है, और रिपॉज़िटरी से जुड़ा Vercel नए कमिट को Production में डिप्लॉय करता है।
5. `अपडेट पूरा हो गया` दिखने पर `रीफ़्रेश करें` दबाकर नया संस्करण लागू करें।

जाँच या बिल्ड विफल होने पर `main` में कमिट नहीं होता, इसलिए वर्तमान प्रोडक्शन डिप्लॉयमेंट वैसा ही बना रहता है। यदि इंस्टॉल में ShareDesk की कोड फ़ाइलें सीधे बदली गई हों, तब भी उन्हें ऊपर से नहीं लिखा जाता — टकराव वाली फ़ाइलों के नाम दिखाकर काम रोक दिया जाता है। विफलता दिखने पर `विस्तृत लॉग देखें` से GitHub Actions का रिकॉर्ड देखा जा सकता है।

### वन-क्लिक अपडेट की तैयारी (एक बार)

ऐप के भीतर से सीधे अपडेट करने के लिए, ShareDesk को अपनी इंस्टॉल रिपॉज़िटरी का workflow चलाने देने हेतु एक बार GitHub टोकन बनाकर Vercel में डालें। यह टोकन केवल आपकी एक इंस्टॉल रिपॉज़िटरी की Actions अनुमति रखने वाला न्यूनतम-अधिकार टोकन है।

1. GitHub में साइन इन करने के बाद ऊपर दाईं ओर प्रोफ़ाइल चित्र → `Settings` खोलें।
2. बाएँ मेन्यू में सबसे नीचे `Developer settings` → `Personal access tokens` → `Fine-grained tokens` खोलें।
3. `Generate new token` दबाएँ।
4. टोकन का नाम पहचानने योग्य रखें। उदा.) `sharedesk-update`
5. `Expiration` (समाप्ति तिथि) तय करें। समाप्ति तिथि बीत जाने पर वन-क्लिक रुक जाता है और केवल फ़ॉलबैक रास्ता बचता है, इसलिए लंबी अवधि चुनें और समाप्ति का समय याद रखें, या समाप्ति के बाद इसी प्रक्रिया से टोकन दोबारा बनाएँ।
6. `Repository access` में `Only select repositories` चुनें और **केवल अपनी एक ShareDesk इंस्टॉल रिपॉज़िटरी** चुनें।
7. `Permissions` → `Repository permissions` में `Actions` को `Read and write` कर दें। बाकी अनुमतियाँ न छेड़ें।
8. `Generate token` दबाकर बने हुए टोकन का मान कॉपी करें। यह मान पेज छोड़ने के बाद दोबारा नहीं दिखता।
9. Vercel प्रोजेक्ट के `Settings` → `Environment Variables` में `Production` एनवायरनमेंट के लिए नीचे दिया गया मान जोड़ें।

```dotenv
SHAREDESK_GITHUB_TOKEN=कॉपी-किया-गया-टोकन-मान
```

10. Production को दोबारा डिप्लॉय करें। एनवायरनमेंट वेरिएबल में किया गया बदलाव मौजूदा डिप्लॉयमेंट पर अपने आप लागू नहीं होता।

टोकन एक गुप्त मान है। इसे सार्वजनिक रिपॉज़िटरी, चैट, इशू या स्क्रीनशॉट में न चिपकाएँ।

### टोकन के बिना फ़ॉलबैक रास्ता

`SHAREDESK_GITHUB_TOKEN` न डालने वाले इंस्टॉल भी अपडेट किए जा सकते हैं। ऐसे में `अभी अपडेट करें` दबाने पर पहले की तरह GitHub का पेज खुलता है।

1. खुले हुए GitHub Actions पेज पर `Run workflow` दबाएँ।
2. सभी जाँचें पास होने पर इंस्टॉल रिपॉज़िटरी के `main` में अपडेट कमिट बनता है।
3. रिपॉज़िटरी से जुड़ा Vercel नए कमिट को Production में डिप्लॉय करता है।

विफलता और टकराव की स्थिति में व्यवहार वन-क्लिक जैसा ही है। जाँच विफल होने पर `main` में कमिट नहीं होता।

GitHub की डिफ़ॉल्ट अनुमतियों से चल रही workflow फ़ाइल को स्वयं बदलने की अनुमति नहीं है। आगे किसी रिलीज़ में यदि ShareDesk के अपडेट कार्य का तरीका बदलता है, तो पुराना workflow चुपचाप बनाए रखने के बजाय काम रोक दिया जाएगा और नीचे दिए `0.2.0 से पुराने इंस्टॉल का एक बार का माइग्रेशन` जैसे एक बार के माइग्रेशन की जानकारी दी जाएगी। उस स्थिति को छोड़कर, ऐप और सामान्य अपडेट कोड तभी नए होते हैं जब व्यवस्थापक ऊपर बताई प्रक्रिया (वन-क्लिक या फ़ॉलबैक) स्वयं शुरू करता है।

यदि अपडेट बटन कहे कि रिपॉज़िटरी कनेक्ट नहीं है, तो Vercel के Production एनवायरनमेंट वेरिएबल में नीचे दिया मान जोड़कर दोबारा डिप्लॉय करें।

```dotenv
SHAREDESK_GITHUB_REPOSITORY=मेरा-GitHub-खाता/मेरी-ShareDesk-रिपॉज़िटरी
```

Deploy with Vercel से बने प्रोजेक्ट में Vercel की Git रिपॉज़िटरी जानकारी अपने आप पहचान ली जाती है, इसलिए यह मान अलग से डालने की आवश्यकता नहीं है। यदि GitHub Actions सफल रहा पर Vercel डिप्लॉय शुरू न हुआ हो, तो Vercel प्रोजेक्ट के `Settings` → `Git` में देखें कि उसी इंस्टॉल रिपॉज़िटरी का `main` Production Branch के रूप में जुड़ा है या नहीं।

## 0.5.0 में बदलने वाला व्यवहार

0.5.0 से हर उपयोगकर्ता की एक भूमिका होती है। अपडेट के बाद निम्न लागू होता है।

- मौजूदा सभी उपयोगकर्ता `संपादित कर सकते हैं` भूमिका के साथ आगे बढ़ते हैं। काम करने का तरीका नहीं बदलता।
- प्रोडक्शन (`STORAGE_DRIVER=drive`) इंस्टॉल में `ACCESS_KEYS` से आने वाले एक्सेस कुंजी अतिथि `केवल देखना` में बदल जाते हैं। एक्सेस कुंजी से फ़ाइलें अपलोड करने या बदलने वाला उपयोग अपडेट के बाद काम नहीं करेगा। local मोड की एक्सेस कुंजी पहले की तरह `संपादित कर सकते हैं` ही रहती है।
- भूमिका व्यवस्थापक स्क्रीन की उपयोगकर्ता तालिका के भूमिका कॉलम से कभी भी बदली जा सकती है।

## 0.2.0 से पुराने इंस्टॉल का एक बार का माइग्रेशन

जिन पुराने इंस्टॉल में अपडेट बटन और workflow नहीं हैं, उनमें नीचे दिया माइग्रेशन **केवल एक बार** करें। पहले इंस्टॉल रिपॉज़िटरी का `main` लोकल में खोलें और देखें कि `git status` में कोई बदलाव न हो।

Windows PowerShell:

```powershell
$shareDeskBootstrap = Join-Path $env:TEMP 'sharedesk-bootstrap.mjs'
Invoke-WebRequest 'https://github.com/Youkamii/sharedesk-template/releases/latest/download/sharedesk-bootstrap.mjs' -OutFile $shareDeskBootstrap
node $shareDeskBootstrap --apply
Remove-Item -LiteralPath $shareDeskBootstrap
```

macOS या Linux:

```bash
sharedesk_bootstrap="$(mktemp)"
curl -fL 'https://github.com/Youkamii/sharedesk-template/releases/latest/download/sharedesk-bootstrap.mjs' -o "$sharedesk_bootstrap"
node "$sharedesk_bootstrap" --apply
rm -f "$sharedesk_bootstrap"
```

स्क्रिप्ट रिलीज़ की फ़ाइल हैश जाँचने के बाद ऐप कोड और अपडेट फ़ाइलें लोकल वर्किंग फ़ोल्डर में लागू करती है। `.env.local`, `.vercel`, `.git` और ShareDesk द्वारा प्रबंधित न की जाने वाली फ़ाइलें नहीं छुई जातीं। यदि मौजूदा कोड आधिकारिक 0.1.0 से भिन्न हो, तो मनमाने ढंग से ऊपर नहीं लिखा जाता — टकराव वाले पथ दिखा दिए जाते हैं।

लागू करने के बाद निम्न चलाएँ।

```powershell
npm ci
npm test
npm run lint
npx tsc --noEmit --incremental false
npm run build
git status --short
```

बदलावों को देखकर इंस्टॉल रिपॉज़िटरी के `main` में कमिट और push करें। Vercel डिप्लॉय पूरा होने पर प्रोडक्शन पते पर व्यवस्थापक साइन-इन और फ़ाइल सूची जाँचें। इसके बाद के संस्करणों के लिए स्क्रीन पर मौजूद `अपडेट` बटन का उपयोग करें।

## मौजूदा इंस्टॉल का अपडेट AI को सौंपना

कोडिंग AI में इंस्टॉल रिपॉज़िटरी खोलकर नीचे दिया अनुरोध हूबहू भेजा जा सकता है।

```text
इस ShareDesk इंस्टॉल को नवीनतम स्थिर संस्करण पर अपडेट करो।

सबसे पहले docs/UPDATE.hi.md पढ़ो और वर्तमान रिपॉज़िटरी, ब्रांच, git status, origin तथा Vercel कनेक्शन की पुष्टि करो। यदि पहले से अपडेट workflow मौजूद है तो स्क्रीन के बटन जैसा ही GitHub Actions प्रवाह इस्तेमाल करो, और न हो तो docs/UPDATE.hi.md में दिया एक बार का bootstrap इस्तेमाल करो।

.env.local, OAuth मान, Drive ID तथा Drive के भीतर की फ़ाइलें, उपयोगकर्ता, आमंत्रण और नोट न बदलो और न ही उन्हें प्रिंट करो। आधिकारिक कोड से भिन्न फ़ाइलें होने के कारण यदि updater टकराव बताए, तो ऊपर मत लिखो — पथ और विकल्प समझाकर रुक जाओ।

बदलाव आवश्यक हों तो पहले इसी इंस्टॉल रिपॉज़िटरी में अपडेट के लिए GitHub इशू बनाओ, और npm test, npm run lint, npx tsc --noEmit --incremental false, npm run build सभी पास होने के बाद उस इशू संख्या के साथ एक ही कमिट बनाओ। केवल अनुमत इंस्टॉल रिपॉज़िटरी को push करो, और जुड़े हुए Vercel के Production डिप्लॉयमेंट तथा प्रोडक्शन पते की पुष्टि करो। स्वचालित जाँच और वास्तविक प्रोडक्शन पुष्टि को अलग-अलग करके रिपोर्ट करो।
```

## लोकल निजी उपयोग

Vercel के बिना केवल लोकल में उपयोग होने वाले इंस्टॉल में, वर्किंग फ़ोल्डर से निम्न कमांड द्वारा नए संस्करण की जाँच की जा सकती है।

```powershell
node scripts/sharedesk-update.mjs --check
```

वास्तव में लागू करने के लिए पहले देखें कि Git वर्किंग फ़ोल्डर साफ़ है, फिर `node scripts/sharedesk-update.mjs --apply` चलाएँ और ऊपर दिए जाँच कमांड दोबारा चलाएँ। लोकल फ़ाइलें `LOCAL_STORAGE_ROOT` में होती हैं, इसलिए कोड अपडेट से अलग उस पूरे फ़ोल्डर का बैकअप लें।
