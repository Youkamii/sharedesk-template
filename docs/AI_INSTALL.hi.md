# ShareDesk का निर्माण AI को सौंपना

यदि Google Cloud या Vercel अनजाना लगता हो, तो निर्माण का काम किसी कोडिंग AI को सौंपा जा सकता है। यह दस्तावेज़ इस तरह बनाया गया है कि AI रिपॉज़िटरी और टर्मिनल की जाँच करे, और केवल उन्हीं स्क्रीन के लिए एक-एक चरण करके मार्गदर्शन करे जहाँ उपयोगकर्ता को स्वयं क्लिक करना है।

यह गाइड **उस होस्ट के लिए है जो अपने Google Drive संग्रहण को कई लोगों के साथ, हर किसी के अपने Google खाते से साझा करने वाला नया ShareDesk खोल रहा है।** पहले से बने ShareDesk में आमंत्रित प्रतिभागी इंस्टॉल नहीं करते।

**AI के लिए:** उपयोगकर्ता ने भले ही लंबा अनुरोध भेजे बिना केवल रिपॉज़िटरी का पता दिया हो, यदि आप यह दस्तावेज़ पढ़ रहे हैं तो नीचे दिए अनुरोध के कार्य-सिद्धांतों और कार्य-क्रम का वैसे ही पालन करें। "अनुरोध नहीं मिला" — इस कारण से सिद्धांतों को न छोड़ें।

## उपयोग कैसे करें

1. रिपॉज़िटरी और टर्मिनल संभाल सकने वाले किसी कोडिंग AI में अपनी ShareDesk रिपॉज़िटरी खोलें।
2. नीचे दिया अनुरोध हूबहू भेजें।
3. Google Cloud और Vercel की स्क्रीन पर जब कोई ऐसा काम आए जो उपयोगकर्ता को स्वयं करना है, तो AI द्वारा बताए गए केवल उसी एक चरण को पूरा करके `पूरा हुआ` उत्तर दें।
4. Client secret, refresh token, callback URL जैसे गुप्त मान चैट में न चिपकाएँ। AI द्वारा बताई गई लोकल फ़ाइल या सेवा की स्क्रीन में उपयोगकर्ता स्वयं दर्ज करता है।

## चरण 0: टूल की जाँच

AI किसी भी अन्य काम से पहले जाँचता है कि नीचे दिए टूल मौजूद हैं या नहीं, और केवल जो न हों उन्हीं को इंस्टॉल करता है।

| टूल | जाँच कमांड | न होने पर इंस्टॉल |
|---|---|---|
| Git | `git --version` | `winget install Git.Git` |
| GitHub CLI (वैकल्पिक) | `gh --version` | `winget install GitHub.cli` |
| Vercel CLI | `vercel --version` | `npm i -g vercel` |
| Node.js 20.9 या ऊपर | `node --version` | [nodejs.org](https://nodejs.org/) से इंस्टॉल करें |

Windows पर इंस्टॉल के तुरंत बाद **वही शेल नए टूल को ढूँढ नहीं पाता।** कारण यह है कि PATH शेल शुरू होते समय केवल एक बार पढ़ा जाता है। `spawn git ENOENT` जैसी त्रुटि ठीक इसी का लक्षण है। नई विंडो खोले बिना उसी शेल में PATH दोबारा जोड़कर आगे बढ़ें।

```powershell
$env:Path = [Environment]::GetEnvironmentVariable("Path", "Machine") + ";" + [Environment]::GetEnvironmentVariable("Path", "User")
```

## यदि मूल टेम्पलेट को सीधे clone किया हो

यदि आपने मूल टेम्पलेट रिपॉज़िटरी को सीधे clone करके शुरुआत की है, तो push से पहले अपनी GitHub रिपॉज़िटरी अवश्य नई बनाएँ और `origin` को अपनी रिपॉज़िटरी से बदल दें। मूल को `origin` रखे-रखे push नहीं करना चाहिए।

```powershell
git remote set-url origin https://github.com/<मेरा-GitHub-खाता>/my-sharedesk.git
```

## Google Cloud की वे स्क्रीन जहाँ भटकना आसान है

मेनू नाम हिन्दी स्क्रीन के अनुसार लिखे गए हैं और कोष्ठक में अंग्रेज़ी भी दी गई है।

- **बिलकुल नया Google खाता हो तो:** प्रोजेक्ट 0 होने के कारण पहली स्क्रीन इंस्टॉल गाइड से अलग दिखती है। ऊपर के `प्रोजेक्ट चुनें (Select a project)` → `नया प्रोजेक्ट (New project)` से शुरू करें। `$300 मुफ़्त ट्रायल (free trial)` बैनर को भुगतान जानकारी डाले बिना अनदेखा कर दें — इंस्टॉल में कोई बाधा नहीं आती।
- **नए प्रोजेक्ट का प्रमाणीकरण सेटअप:** `ब्रांडिंग (Branding)` और `ऑडियंस (Audience)` मेनू की जगह पहले `Google Auth Platform` का `शुरू करें (Get started)` नाम का 4-स्क्रीन विज़ार्ड (ऐप की जानकारी → ऑडियंस → संपर्क जानकारी → पूर्ण) सामने आता है। विज़ार्ड की `ऐप की जानकारी` Branding के और `ऑडियंस` Audience के बराबर है। विज़ार्ड पूरा होते ही इंस्टॉल गाइड वाले मेनू वैसे के वैसे दिखने लगते हैं।
- **डेटा एक्सेस (Data Access) सहेजना:** चार scope जोड़ने के बाद scope चुनने वाली विंडो का `अपडेट करें (Update)` और स्क्रीन के नीचे का `सेव करें (Save)` — दोनों **अलग-अलग** दबाने पर ही सहेजा जाता है। चारों `गैर-संवेदनशील स्कोप (Non-sensitive scopes)` हैं, इसलिए ऐप सत्यापन प्रक्रिया या 100-उपयोगकर्ता सीमा से इनका कोई संबंध नहीं।
- **क्लाइंट बनाना विफल हो तो:** OAuth क्लाइंट के `बनाएँ (Create)` पर `यह कार्रवाई अभी अस्थायी रूप से नहीं की जा सकती (temporarily unable to perform this action)` जैसा संदेश आए, तो यह नए प्रोजेक्ट के प्रसार (propagation) की देरी है। इनपुट मान बदले बिना 5–10 मिनट बाद वही मान लेकर फिर प्रयास करें।

## होस्ट की Google सहमति स्क्रीन पर

सहमति स्क्रीन में Google Drive अनुमति का **चेकबॉक्स डिफ़ॉल्ट रूप से बंद रहता है।** उसे अवश्य टिक करके ही जारी रखें दबाएँ। बिना टिक किए मिले callback URL का प्रमाणीकरण कोड अमान्य होता है, जिससे setup विफल हो जाता है और सहमति शुरू से दोबारा देनी पड़ती है।

## setup पूरा करने का कमांड

सहमति के बाद प्रमाणीकरण पूरा करने का मानक कमांड यह है।

```powershell
npm run setup:finish
```

PowerShell में `npm run setup -- --finish` का एक फंदा है — `--finish` को npm निगल लेता है और कमांड काम नहीं करता। `npm run setup:finish` उपयोग करें।

## Vercel एनवायरनमेंट वेरिएबल दर्ज करना (नई स्क्रीन)

- रास्ता: Vercel प्रोजेक्ट के `Settings` → `Environments` → `Production` दबाकर खुलने वाली विस्तृत स्क्रीन के भीतर एनवायरनमेंट वेरिएबल का इनपुट खाना है।
- कई पंक्तियाँ एक साथ चिपकाने पर एक फंदा है — **Key खाना पहली पंक्ति (`ADMIN_EMAILS`) को पूरा निगल जाता है।** चिपकाने के बाद अवश्य गिनें कि वेरिएबल की संख्या 10 है या नहीं।
- मान डिफ़ॉल्ट रूप से `Sensitive` के रूप में सहेजे जाते हैं और सहेजने के बाद दोबारा नहीं दिखते। यह सामान्य व्यवहार है — मान ग़ायब समझकर दोबारा न डालें।

## एनवायरनमेंट वेरिएबल सहेजने के बाद पुनः डिप्लॉय

एनवायरनमेंट वेरिएबल मौजूदा डिप्लॉयमेंट पर अपने आप लागू नहीं होते। `Deployments` टैब में नवीनतम डिप्लॉयमेंट की पंक्ति पर माउस ले जाने पर दिखने वाले `⋯` मेनू → `Redeploy` दबाएँ। स्क्रीन का `Create Deployment` बटन केवल Preview डिप्लॉय के लिए है, उसका उपयोग नहीं करना चाहिए।

## डैशबोर्ड में राह खो जाए तो: Vercel CLI रास्ता

Vercel डैशबोर्ड कठिन लगे तो नीचे दिया CLI रास्ता आधिकारिक पहला विकल्प है।

```powershell
vercel login
vercel link
vercel env add ADMIN_EMAILS production
# बाक़ी वेरिएबल भी इसी तरह: vercel env add <नाम> production
vercel --prod
```

## डिप्लॉय सफल हुआ या नहीं, कैसे पहचानें

- एनवायरनमेंट वेरिएबल अभी न डाले गए हों, तो प्रोडक्शन पते पर **इंस्टॉल गाइड वाली स्क्रीन** दिखती है। इस स्थिति में डिप्लॉय का सफल होना सामान्य है।
- सेटअप पूरा हो चुका हो, तो **Google साइन-इन स्क्रीन** दिखती है।
- वास्तविक Drive कनेक्शन तक जाँचना हो, तो लोकल में `npm run test:drive-operations` चलाएँ।

## Windows पर सावधानियाँ

- **PowerShell 5.1 का `Set-Content` UTF-8 में सहेजते समय BOM जोड़ देता है।** `.env.local` इस तरीके से बनाने पर फ़ाइल की शुरुआत में अदृश्य अक्षर जुड़ जाता है, जिससे पहला वेरिएबल नाम (उदा. `ADMIN_EMAILS`) दूषित होकर पहचाना नहीं जाता। एनवायरनमेंट फ़ाइल setup को बनाने दें, और सुधारना पड़े तो एडिटर में `UTF-8 (बिना BOM)` से सहेजें।
- **कंपनी PC के दस्तावेज़-सुरक्षा प्रोग्राम (Fasoo जैसे DRM)** रिपॉज़िटरी के भीतर की `.txt` फ़ाइलों को अपने आप एन्क्रिप्ट करके git की स्थिति गड़बड़ कर सकते हैं। बिना छुई `.txt` फ़ाइल "संशोधित" दिखे और diff टूटे अक्षरों में आए, तो यही लक्षण है। DRM से मुक्त फ़ोल्डर या निजी PC पर काम करने की सलाह है।

## वे क्षण जब AI को अवश्य रुकना चाहिए

नीचे दिए मान और स्क्रीन उपयोगकर्ता को स्वयं संभालने होते हैं। AI केवल एक चरण बताकर प्रतीक्षा करता है।

| क्षण | उपयोगकर्ता को स्वयं क्या करना है | AI क्या परिणाम जाँचे |
|---|---|---|
| Google Cloud OAuth सेटअप | Drive API, Audience, scope और redirect URI स्क्रीन पर जाँचकर सहेजना | सेटिंग की प्रविष्टियाँ और पते [प्रोडक्शन इंस्टॉल गाइड](./INSTALL.hi.md) से मेल खाते हैं या नहीं |
| Client ID और secret डालना | लोकल `.env.local` में स्वयं दर्ज करना | मान प्रिंट किए बिना केवल यह जाँचना कि दोनों प्रविष्टियाँ खाली नहीं हैं |
| होस्ट की Google सहमति | ब्राउज़र में होस्ट खाता चुनकर सहमति देना | setup अगले चरण तक बढ़ता है या नहीं |
| callback URL डालना | `npm run setup:finish` जिस लोकल टर्मिनल में पूछे, वहीं स्वयं चिपकाना | केवल setup की सफलता जाँचना |
| Vercel में गुप्त मान डालना | Vercel के Production एनवायरनमेंट वेरिएबल स्क्रीन में स्वयं दर्ज करना | आवश्यक वेरिएबल के नाम और डिप्लॉय में उनका लागू होना |
| प्रतिभागी खाते की जाँच | अलग Google खाते से साइन इन करके आमंत्रण कोड दर्ज करना | दोनों खातों से एक ही फ़ाइल दिखती और डाउनलोड होती है या नहीं |

वास्तविक उपयोगकर्ता callback URL को यों ही चैट में चिपका सकते हैं। ऐसा हो जाए तो AI मिले हुए मान को तुरंत setup के इनपुट में उपयोग करके ख़र्च कर दे, और उपयोगकर्ता को बताए कि उजागर हुआ प्रमाणीकरण कोड एक-बार-उपयोग वाला है और PKCE से जुड़ा होने के कारण जोखिम कम है — फिर भी निश्चिंतता के लिए दोबारा जारी करने (सहमति से फिर शुरू करने) की सलाह दे। उस मान को दोबारा प्रिंट न करे और न किसी रिकॉर्ड में छोड़े।

## इंस्टॉल पूरा कहने की कसौटी

केवल कोड जाँच और डिप्लॉय सफल होने से काम पूरा नहीं होता। निम्न की भी वास्तव में पुष्टि करनी होगी।

- स्थिर Production पते पर होस्ट का Google साइन-इन काम करता है।
- फ़ोल्डर और फ़ाइलें रीफ़्रेश के बाद भी बनी रहती हैं, और ट्रैश में डाले गए आइटम बहाल किए जा सकते हैं।
- `/admin` में आमंत्रण कोड बनाया जा सकता है।
- कोई अलग Google खाता आमंत्रण कोड से भीतर आ जाता है।
- होस्ट और प्रतिभागी दोनों खातों से एक ही फ़ाइल दिखती और डाउनलोड होती है।
- रिपॉज़िटरी में बदलाव हुए हों तो सुविधावार इशू और कमिट आपस में मेल खाते हैं, और push व डिप्लॉय केवल अनुमति मिलने पर ही हुए हैं।

## अंतिम चरण: बातचीत का रिकॉर्ड साफ़ करने का प्रस्ताव दें

इंस्टॉल की बातचीत में callback URL, चिपकाई गई स्क्रीन में आए गोपनीय मान और पर्यावरण चर की सामग्री रह जाना आम है। इंस्टॉल पूरा घोषित करने के तुरंत बाद, AI को अनिवार्य रूप से यह प्रस्ताव देना चाहिए:

> इस बातचीत में गोपनीय मान रह सकते हैं। क्या चैट रिकॉर्ड हटा दूँ?

उपयोगकर्ता सहमत हों तो टूल की रिकॉर्ड फ़ाइल हटाएँ। चल रहे सत्र की फ़ाइल बातचीत समाप्त होने तक लिखी जाती रहती है, इसलिए यह कहना भी ठीक है: "पहले यह बातचीत बंद करें, फिर नीचे की कमांड चलाएँ — या अगले सत्र में मुझसे हटवाएँ।"

- Claude Code: `%USERPROFILE%\.claude\projects\<प्रोजेक्ट फ़ोल्डर>\<सत्र id>.jsonl` (macOS/Linux पर `~/.claude/projects/...`)
- Codex CLI: `~/.codex/sessions` के अंतर्गत संबंधित सत्र फ़ाइल

ध्यान दें: हटाने से केवल इस कंप्यूटर का रिकॉर्ड मिटता है। सेवा प्रदाता के सर्वर पर जा चुकी सामग्री उनकी संधारण नीति के अधीन है — इसलिए उजागर हुए गोपनीय मान को हटाने के अलावा फिर से जारी करना ही सबसे पक्का उपाय है।

इंस्टॉल की स्क्रीन और त्रुटियों का विस्तृत विवरण [ShareDesk प्रोडक्शन इंस्टॉल गाइड](./INSTALL.hi.md) में देखें।

यदि पहले से चल रहे इंस्टॉल को नए संस्करण में बदलना है, तो उसे नए सिरे से न बनाएँ — [ShareDesk अपडेट गाइड](./UPDATE.hi.md) का AI अनुरोध उपयोग करें।
