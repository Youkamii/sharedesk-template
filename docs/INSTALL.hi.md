# ShareDesk प्रोडक्शन इंस्टॉल गाइड

यह दस्तावेज़ बताता है कि ShareDesk को इस तरह कैसे खोलें कि एक होस्ट के Google Drive संग्रहण को कई लोग अपने-अपने Google खाते से साथ मिलकर उपयोग कर सकें।

यदि Google Cloud या Vercel की सेटिंग अनजानी लगती हो, तो सब कुछ स्वयं करने की आवश्यकता नहीं है। [निर्माण AI को सौंपना](./AI_INSTALL.hi.md) में दिया अनुरोध किसी कोडिंग AI को भेजने पर वह पहले यह जाँचता है कि कौन-से चरण पूरे हो चुके हैं, और केवल उन्हीं स्क्रीन पर एक-एक चरण करके मार्गदर्शन करता है जहाँ उपयोगकर्ता को स्वयं कुछ करना है।

## पहले, मेरी भूमिका क्या है?

### प्रतिभागी

यदि आपको किसी के बनाए ShareDesk में आमंत्रित किया गया है, तो **इस दस्तावेज़ के अनुसार इंस्टॉल न करें।** होस्ट द्वारा भेजे गए ShareDesk पते पर अपने Google खाते से साइन इन करें और आमंत्रण कोड दर्ज कर दें। GitHub खाता, Vercel प्रोजेक्ट या Google OAuth क्लाइंट की आवश्यकता नहीं है।

### होस्ट

अपने Google Drive की जगह देकर एक नया ShareDesk पता बनाना और लोगों को आमंत्रित करना हो, तो नीचे दिए चरणों का पालन करें। इंस्टॉल केवल होस्ट एक बार करता है, और प्रतिभागी उसी पते तथा संग्रहण का साथ मिलकर उपयोग करते हैं।

हर इंस्टॉल के साथ होस्ट की Git रिपॉज़िटरी, Vercel प्रोजेक्ट, Google OAuth क्लाइंट और Drive रूट अलग-अलग जुड़ते हैं। यह अलगाव होस्ट के इंस्टॉल-स्वामित्व की व्याख्या है; ShareDesk का पहला उपयोग-मूल्य यह है कि एक Drive संग्रहण को कई लोग साथ मिलकर उपयोग करें। यदि कोई सेटिंग पहले से बनी हुई है, तो नई न बनाएँ — उसी को आगे उपयोग करें।

## होस्ट के लिए त्वरित रास्ता

1. **ShareDesk पता बनाना:** [Deploy with Vercel](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FYoukamii%2Fsharedesk-template&project-name=my-sharedesk&repository-name=my-sharedesk) से अपनी GitHub रिपॉज़िटरी और Vercel प्रोजेक्ट बनाएँ और Production पता नोट कर लें।
2. **Google कनेक्शन बनाना:** Google Cloud में Drive API चालू करें और Web application OAuth क्लाइंट बनाएँ। सटीक स्कोप और callback पते [चरण 2](#2-google-cloud-सेटअप) से कॉपी करें।
3. **होस्ट Drive कनेक्ट करना:** रिपॉज़िटरी लेकर `npm ci`, `npm run setup` चलाएँ। `.env.local` न हो तो setup उसे अपने आप बना देता है। Client ID और secret डालकर दोबारा चलाने पर प्रमाणीकरण पेज ब्राउज़र में अपने आप खुल जाता है। सहमति देने के बाद `npm run setup:finish` से पूरा करें।
4. **प्रोडक्शन से जोड़ना:** setup द्वारा भरे गए आवश्यक मान Vercel के Production एनवायरनमेंट वेरिएबल में ले जाएँ और दोबारा डिप्लॉय करें।
5. **एक व्यक्ति के साथ जाँचना:** पहले प्रोडक्शन साइन-इन और फ़ाइल सहेजना जाँचें, फिर `/admin` में आमंत्रण कोड बनाएँ। एक व्यक्ति को आमंत्रित करके यह देख लें कि दोनों खातों में एक ही फ़ाइल दिखती है — यह हो जाने पर मुख्य इंस्टॉल पूरा हो जाता है। Vercel Firewall उसके बाद वाले प्रोडक्शन सुरक्षा चरण में सेट किया जाता है।

ShareDesk नया संस्करण अपने आप लागू नहीं करता। इंस्टॉल के बाद टास्कबार का `अपडेट` बटन (जो केवल व्यवस्थापक को दिखता है) तभी तारा दिखाता है जब नया संस्करण उपलब्ध हो। पुराने इंस्टॉल को पहली बार जोड़ने का तरीका [अपडेट गाइड](./UPDATE.hi.md) में है।

नीचे हर चरण का विस्तृत विवरण है। आप चाहें तो केवल वही हिस्सा देख लें जिसमें Google Cloud की स्क्रीन आई हो या कोई त्रुटि सामने आई हो।

## इंस्टॉल पूरा होने की कसौटी

निम्न सभी बातों की पुष्टि होने पर ही प्रोडक्शन इंस्टॉल पूरा माना जाता है।

- मेरी Git रिपॉज़िटरी और मेरा Vercel प्रोजेक्ट आपस में जुड़े हुए हैं।
- एक ऐसा Production पता मौजूद है जो बदलता नहीं।
- Google OAuth क्लाइंट में प्रोडक्शन callback ठीक-ठीक पंजीकृत है।
- Vercel के Production एनवायरनमेंट में प्रोडक्शन के आवश्यक मान मौजूद हैं।
- प्रोडक्शन पते पर होस्ट का Google साइन-इन काम करता है।
- `/files` में बनाया गया फ़ोल्डर रीफ़्रेश के बाद भी बना रहता है।
- स्क्रीन के नीचे दाईं ओर टास्कबार से अलग रखा ट्रैश आइकन दिखता है, और आइकन दबाकर हटाए गए आइटम बहाल किए जा सकते हैं।
- `/admin` खुलता है और आमंत्रण कोड की वैधता अवधि तथा उपयोग प्रकार चुने जा सकते हैं।
- आमंत्रण कोड से एक व्यक्ति अपने Google खाते से जुड़ चुका है।
- होस्ट और प्रतिभागी — दोनों खातों से एक ही फ़ाइल देखी और डाउनलोड की जा सकती है।

### कौन-से खाते जुड़े हैं, यह जाँचें

कंप्यूटर पर पहले से कोई दूसरा GitHub या Vercel खाता साइन-इन हो, तो रिपॉज़िटरी और प्रोजेक्ट ग़लत खाते में बन जाते हैं। शुरू करने से पहले जाँच लें।

```powershell
gh auth status
vercel whoami
git config --global user.email
```

कोई दूसरा खाता दिखे तो इस क्रम से दोबारा साइन इन करें।

1. `gh auth logout` के बाद `gh auth login` से उपयोग करने वाले GitHub खाते में साइन इन करें।
2. `vercel logout` के बाद `vercel login` से उपयोग करने वाले Vercel खाते में साइन इन करें।
3. `git config --global user.email "उपयोग-करने-वाला-ईमेल"` से कमिट ईमेल मिलाएँ।

## 1. रिपॉज़िटरी और स्थिर प्रोडक्शन पता तैयार करना

यदि वर्तमान रिपॉज़िटरी का `origin` आपकी अपनी रिपॉज़िटरी है और वह पहले से किसी Vercel प्रोजेक्ट से जुड़ी है, तो यह चरण न दोहराएँ। `git remote -v` और Vercel प्रोजेक्ट सेटिंग जाँचकर मौजूदा प्रोजेक्ट का ही उपयोग करें।

यदि अभी रिपॉज़िटरी और Vercel प्रोजेक्ट नहीं हैं, तो नीचे दिए बटन से दोनों एक साथ बनाएँ।

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2FYoukamii%2Fsharedesk-template&project-name=my-sharedesk&repository-name=my-sharedesk)

Vercel के बिना केवल रिपॉज़िटरी पहले बनानी हो तो [Use this template](https://github.com/Youkamii/sharedesk-template/generate) का उपयोग करें।

### नए खाते में Create बटन न दबे तो

Vercel पहली बार उपयोग करने वाले खाते में `Git Scope` खाली रहता है, इसलिए `Create` बटन निष्क्रिय रहता है। `Select Git Scope` ड्रॉपडाउन → `Add GitHub Account` दबाकर GitHub ऐप इंस्टॉल करें (`All repositories` चुनें), तो `Create` सक्रिय हो जाता है। इस प्रक्रिया में GitHub विंडो पॉपअप के रूप में खुलती है, इसलिए ब्राउज़र का पॉपअप ब्लॉकर भी जाँच लें।

पहले डिप्लॉय में एनवायरनमेंट वेरिएबल खाली हों तब भी चलेगा। साइन-इन बटन के बजाय इंस्टॉल गाइड दिखना सामान्य है। इस चरण में नीचे दिए दो पते नोट कर लें।

- मेरी Git रिपॉज़िटरी: उदा.) `https://github.com/my-account/my-sharedesk`
- स्थिर Production पता: उदा.) `https://my-sharedesk.vercel.app`

हर कमिट के साथ बदलने वाला Preview पता या लंबा डिप्लॉयमेंट पता नहीं, बल्कि प्रोजेक्ट के साथ हमेशा जुड़ा रहने वाला Production पता उपयोग करें।

प्रोजेक्ट का नाम कोई और पहले ले चुका हो, तो पते में `-theta` जैसा प्रत्यय जुड़ सकता है। अपना स्थिर पता Vercel प्रोजेक्ट के `Domains` टैब में `.vercel.app` पर समाप्त होने वाले पते से जाँचें। बीच में हैश वाला लंबा डिप्लॉयमेंट पता उपयोग न करें।

## 2. Google Cloud सेटअप

### 2-1. प्रोजेक्ट और Drive API

1. [Google Cloud Console](https://console.cloud.google.com/) खोलें।
2. उपयोग करने वाला प्रोजेक्ट चुनें या नया प्रोजेक्ट बनाएँ।
3. `API और सेवाएँ` → `लाइब्रेरी` में `Google Drive API` चालू करें।

OAuth क्लाइंट और Drive API को एक ही Cloud प्रोजेक्ट में रखें।

### 2-2. Branding

`Google Auth Platform` → `Branding` में नीचे दिए मान भरें।

- ऐप का नाम: उदा.) `हमारी टीम का ShareDesk`
- उपयोगकर्ता सहायता ईमेल
- डेवलपर संपर्क ईमेल

Google Cloud की स्क्रीन भाषा के अनुसार ये `ब्रांडिंग`, `ऑडियंस`, `डेटा एक्सेस`, `क्लाइंट` जैसे अनूदित रूप में दिख सकते हैं।

### 2-3. Audience

`Google Auth Platform` → `Audience` में उपयोग का दायरा तय करें।

- व्यक्तिगत Google खाते या संगठन के बाहर के लोगों को भी आमंत्रित करना हो तो `External`
- केवल एक Google Workspace संगठन के भीतर उपयोग करना हो तो संगठन की नीति के अनुसार `Internal`

प्रोडक्शन के लिए बने External ऐप को setup से पहले `Publish app` दबाकर `In production` में बदल दें। यदि पहले से `In production` है तो उसे वैसा ही रहने दें।

`Testing` में भी इंस्टॉल किया जा सकता है, पर ShareDesk का होस्ट कनेक्शन `drive.file` और ऑफ़लाइन एक्सेस दोनों माँगता है। इस स्थिति में मिला refresh token आमतौर पर 7 दिन बाद समाप्त हो जाता है। यदि आपने Testing स्थिति में ही setup कर लिया है, तो पहले In production में बदलें और फिर होस्ट कनेक्शन दोबारा करें। जो ऐप पहले से In production है, उसके ठीक चल रहे टोकन बिना कारण रद्द न करें।

`In production` एक प्रकाशन स्थिति है, जो परीक्षण वाले टोकन की समाप्ति नीति से अलग है। इसका अर्थ ऐप सत्यापन पूरा होना नहीं है — Branding और उपयोगकर्ताओं की संख्या के अनुसार Google की चेतावनी या अतिरिक्त सत्यापन प्रक्रिया शेष रह सकती है।

स्थितियों का विस्तृत विवरण [Google OAuth Audience गाइड](https://support.google.com/cloud/answer/15549945?hl=hi) में देखें।

### 2-4. Data Access

`Google Auth Platform` → `Data Access` → `Add or remove scopes` में नीचे दिए चार स्कोप जोड़ें।

```text
openid
https://www.googleapis.com/auth/userinfo.email
https://www.googleapis.com/auth/userinfo.profile
https://www.googleapis.com/auth/drive.file
```

### 2-5. Web application OAuth क्लाइंट

`Google Auth Platform` → `Clients` में पहले देखें कि कोई मौजूदा Web application क्लाइंट है या नहीं। यदि काम आने वाला कोई क्लाइंट पहले से है, तो नया न बनाएँ — केवल छूटे हुए पते जोड़ दें।

नया बनाना हो तो इस तरह सेट करें।

1. Application type: `Web application`
2. नाम: उदा.) `ShareDesk web`
3. `Authorized JavaScript origins`: खाली छोड़ें
4. `Authorized redirect URIs`: नीचे दिए तीन पते पंजीकृत करें

```text
http://127.0.0.1:53682/callback
http://localhost:3000/api/auth/google/callback
https://my-sharedesk.vercel.app/api/auth/google/callback
```

अंतिम पते का डोमेन बदलकर वही वास्तविक Production डोमेन लगाएँ जो चरण 1 में मिला था।

प्रोडक्शन callback को `Authorized JavaScript origins` में नहीं डालना चाहिए। JavaScript origin में पथ नहीं डाला जा सकता और ShareDesk उस खाने का उपयोग नहीं करता। तीनों पते `Authorized redirect URIs` में ही डालें।

रीडायरेक्ट पता `http`/`https`, होस्ट, पोर्ट, पथ और अंत के स्लैश तक बिलकुल एक जैसा होना चाहिए। Google की [OAuth वेब सर्वर गाइड](https://developers.google.com/identity/protocols/oauth2/web-server#uri-validation) में भी सटीक मिलान आवश्यक बताया गया है।

क्लाइंट बनाने के बाद Client ID और Client secret सुरक्षित रूप से नोट कर लें। अगले चरण में इनकी आवश्यकता होगी। इन्हें सार्वजनिक रिपॉज़िटरी, चैट, इशू या स्क्रीनशॉट में न चिपकाएँ।

## 3. लोकल एनवायरनमेंट फ़ाइल तैयार करना

यदि वर्तमान रिपॉज़िटरी पहले से लोकल में खुली है, तो दोबारा clone न करें — उसी फ़ोल्डर से शुरू करें।

अभी तक न ली हो, तो चरण 1 में बनाई अपनी रिपॉज़िटरी clone करें।

```powershell
git clone https://github.com/<मेरा-GitHub-खाता>/my-sharedesk.git
cd my-sharedesk
```

निर्भरताएँ इंस्टॉल करें और setup एक बार चलाएँ।

```powershell
npm ci
npm run setup
```

`.env.local` न हो तो सादा `npm run setup` उसे केवल-स्वामी अनुमति के साथ अपने आप बनाता है और `.env.example` की सामग्री उसमें डाल देता है। Client ID और secret खाली होने की सूचना आना सामान्य है। मौजूदा `.env.local` हो तो उसकी सामग्री ऊपर से नहीं लिखी जाती, केवल अनुमतियाँ जाँची जाती हैं।

केवल एनवायरनमेंट फ़ाइल पहले से तैयार करनी हो और setup शुरू न करना हो, तो पुराना संगत कमांड `npm run setup -- --prepare-env` भी उपयोग किया जा सकता है।

`.env.local` में नीचे दिए दो मान स्वयं भरें।

```dotenv
GOOGLE_CLIENT_ID=जारी-किया-गया-client-id
GOOGLE_CLIENT_SECRET=जारी-किया-गया-client-secret
```

इन मानों को कोडिंग एजेंट की चैट या कमांड लाइन आर्ग्युमेंट के रूप में न दें।

## 4. होस्ट Drive कनेक्ट करना

यदि मौजूदा `.env.local` में मान्य `GOOGLE_REFRESH_TOKEN`, `DRIVE_ROOT_FOLDER_ID` और `DRIVE_STATE_FOLDER_ID` तीनों मौजूद हैं और वास्तव में काम कर रहे हैं, तो setup दोबारा चलाने की आवश्यकता नहीं है। नया इंस्टॉल हो या कनेक्शन दोबारा जारी करना हो, तभी नीचे दिया क्रम अपनाएँ।

### 4-1. प्रमाणीकरण शुरू करना

```powershell
npm run setup
```

1. setup डिफ़ॉल्ट ब्राउज़र में Google प्रमाणीकरण पेज खोलता है। यदि अपने आप न खुले, तो टर्मिनल में छपा हुआ URL स्वयं खोलें।
2. जिस Google खाते को ShareDesk का होस्ट बनाना है, उससे साइन इन करके सहमति दें।
3. ब्राउज़र `http://127.0.0.1:53682/callback?...` पर चला जाता है।
4. ब्राउज़र में कनेक्शन विफल दिखे तब भी यह सामान्य है। एड्रेस बार का पूरा पता कॉपी करें।

callback URL में थोड़ी देर के लिए मान्य एक-बार-उपयोग वाला प्रमाणीकरण कोड होता है। इसे केवल उसी कंप्यूटर के टर्मिनल में चिपकाएँ, चैट, इशू या स्क्रीनशॉट से साझा न करें।

### 4-2. प्रमाणीकरण पूरा करना

```powershell
npm run setup:finish
```

प्रश्न आने पर अभी कॉपी किया हुआ पूरा callback URL चिपका दें। URL को कमांड आर्ग्युमेंट के रूप में नहीं लिखा जाता, इसलिए शेल इतिहास में प्रमाणीकरण कोड नहीं रहता।

यदि आप किसी कोडिंग एजेंट के साथ काम कर रहे हैं, तो यह इनपुट उपयोगकर्ता स्वयं देता है। एजेंट callback URL को चैट में न माँगे और न ही टर्मिनल आउटपुट से दोबारा पढ़े — वह इनपुट पूरा होने तक प्रतीक्षा करता है।

setup पूरा होने पर `.env.local` में नीचे दिए मान तैयार हो जाते हैं।

- `ADMIN_EMAILS`
- `SESSION_SECRET`
- `STORAGE_DRIVER=drive`
- `GOOGLE_REFRESH_TOKEN`
- `DRIVE_ROOT_FOLDER_ID`
- `DRIVE_STATE_FOLDER_ID`

साथ ही होस्ट के Drive में `ShareDesk` रूट और `.sharedesk` स्थिति फ़ोल्डर बनाए जाते हैं। मौजूदा स्थिति फ़ाइलों को मनमाने ढंग से ऊपर से नहीं लिखा जाता।

## 5. लोकल जाँच

```powershell
npm run dev
```

1. `http://localhost:3000` खोलें।
2. होस्ट Google खाते से साइन इन करें।
3. `/files` में एक फ़ोल्डर बनाएँ और देखें कि रीफ़्रेश के बाद भी बना रहता है या नहीं।
4. जाँचें कि `/admin` खुलता है।

यहाँ तक की जाँच केवल लोकल जाँच है। इसका अर्थ यह नहीं कि वह प्रोडक्शन डिप्लॉय पूरा हो गया जिससे दूसरे लोग इसका उपयोग कर सकें।

## 6. Vercel Production एनवायरनमेंट वेरिएबल और पुनः डिप्लॉय

चरण 1 में बनाया गया मौजूदा Vercel प्रोजेक्ट खोलें। `Settings` → `Environment Variables` में नीचे दिए मान Production एनवायरनमेंट में डालें। हाल की स्क्रीन में `Settings` → `Environments` → `Production` दबाकर खुलने वाली विस्तृत स्क्रीन के भीतर एनवायरनमेंट वेरिएबल का इनपुट खाना है।

| नाम | मान |
|---|---|
| `ADMIN_EMAILS` | व्यवस्थापक का Google ईमेल। एक से अधिक हों तो अल्पविराम से अलग करें |
| `SESSION_SECRET` | setup द्वारा बनाया गया लंबा यादृच्छिक मान |
| `STORAGE_DRIVER` | `drive` |
| `GOOGLE_CLIENT_ID` | Web application Client ID |
| `GOOGLE_CLIENT_SECRET` | Client secret |
| `GOOGLE_REFRESH_TOKEN` | setup द्वारा प्राप्त होस्ट refresh token |
| `DRIVE_ROOT_FOLDER_ID` | setup द्वारा बनाए गए ShareDesk फ़ोल्डर की ID |
| `DRIVE_STATE_FOLDER_ID` | setup द्वारा बनाए गए स्थिति फ़ोल्डर की ID |
| `PUBLIC_BASE_URL` | स्थिर Production origin। उदा.: `https://my-sharedesk.vercel.app` |
| `SHAREDESK_DEFAULT_LOCALE` | (वैकल्पिक) डेस्क की डिफ़ॉल्ट भाषा (en/ko/ja/hi/zh), जो setup में चुनी गई — `.env.local` का मान वैसा ही कॉपी करें |
| `SHAREDESK_GITHUB_TOKEN` | (वैकल्पिक) वन-क्लिक अपडेट के लिए fine-grained PAT — [अपडेट गाइड](./UPDATE.hi.md) देखें |

इंस्टॉल में होने वाली गलतियाँ कम करने के लिए Vercel Production में `PUBLIC_BASE_URL=https://वास्तविक-प्रोडक्शन-डोमेन` स्पष्ट रूप से लिखें। यह मान लोकल `.env.local` में नहीं डाला जाता, क्योंकि लोकल ऐप का साइन-इन `http://localhost:3000` पर लौटना चाहिए।

`PUBLIC_BASE_URL` छोड़ देने पर ShareDesk उसके बदले `VERCEL_PROJECT_PRODUCTION_URL` का उपयोग करता है। यह तरीका अपनाएँ तो जाँच लें कि Vercel प्रोजेक्ट में सिस्टम एनवायरनमेंट वेरिएबल उजागर करने का विकल्प चालू है।

`PUBLIC_BASE_URL` में केवल origin डालें। पथ, अंत का स्लैश, callback पथ या Preview URL न जोड़ें।

`ACCESS_KEYS` केवल तभी डालें जब अस्थायी अतिथियों के लिए कुंजी उपयोग करनी हो। drive मोड में एक्सेस कुंजी से आने वाला अतिथि `केवल देखना` होता है। `LOCAL_STORAGE_ROOT` और `SHAREDESK_SHARE_TEST_EMAIL` प्रोडक्शन एनवायरनमेंट में न डालें। किसी भी गुप्त मान पर `NEXT_PUBLIC_` उपसर्ग न लगाएँ।

कई मान एक साथ चिपकाते समय एक फंदा है — Key खाना पहली पंक्ति (`ADMIN_EMAILS`) को पूरा निगल जाता है। चिपकाने के बाद अवश्य जाँचें कि वेरिएबल की संख्या 9 है (वैकल्पिक प्रविष्टि छोड़कर)। मान डिफ़ॉल्ट रूप से `Sensitive` के रूप में सहेजे जाते हैं और सहेजने के बाद दोबारा नहीं दिखते — यह सामान्य है।

एनवायरनमेंट वेरिएबल डालने या बदलने के बाद Production दोबारा डिप्लॉय करें। एनवायरनमेंट वेरिएबल का बदलाव मौजूदा डिप्लॉयमेंट पर अपने आप लागू नहीं होता। `Deployments` टैब में नवीनतम डिप्लॉयमेंट की पंक्ति पर माउस ले जाने पर दिखने वाले `⋯` मेनू → `Redeploy` दबाएँ। `Create Deployment` बटन केवल Preview डिप्लॉय के लिए है, उसका उपयोग न करें। विस्तृत व्यवहार के लिए [Vercel एनवायरनमेंट वेरिएबल गाइड](https://vercel.com/docs/environment-variables) देखें।

## 7. प्रोडक्शन जाँच

स्थिर Production पते पर सीधे जाँच करें।

1. होस्ट Google खाते से साइन इन करें।
2. `/files` में एक टेस्ट फ़ोल्डर बनाएँ और देखें कि रीफ़्रेश के बाद भी बना रहता है या नहीं।
3. टेस्ट फ़ोल्डर हटाने के बाद स्क्रीन के नीचे दाईं ओर मौजूद ट्रैश आइकन दबाकर ट्रैश विंडो खोलें और फ़ोल्डर बहाल करें। यह भी देखें कि आइकन टास्कबार के बाहर है और खुली विंडो से ओवरलैप होने पर विंडो के पीछे चला जाता है।
4. जाँचें कि `/admin` खुलता है।
5. आमंत्रण कोड बनाने की स्क्रीन पर देखें कि वैधता अवधि `1 घंटा`, `24 घंटे`, `7 दिन`, `30 दिन` और उपयोग प्रकार `एकल-उपयोग`, `समाप्ति तक असीमित` चुने जा सकते हैं। यह भी देखें कि जुड़ने वाले की शुरुआती भूमिका `संपादित कर सकते हैं` (डिफ़ॉल्ट), `अपलोड कर सकते हैं`, `केवल देखना` में से चुनी जा सकती है।
6. साइन आउट करके दोबारा साइन इन करें और देखें कि प्रोडक्शन callback ठीक काम करता है।
7. `/admin` में एक आमंत्रण कोड बनाएँ और साथ उपयोग करने वाले किसी एक व्यक्ति को प्रोडक्शन पता तथा कोड भेजें।
8. प्रतिभागी अपने Google खाते से साइन इन करके आमंत्रण कोड दर्ज करता है। प्रतिभागी को OAuth क्लाइंट या Vercel प्रोजेक्ट की आवश्यकता नहीं होती।
9. होस्ट एक टेस्ट फ़ाइल अपलोड करे, और जाँचें कि होस्ट व प्रतिभागी दोनों खातों से वही फ़ाइल दिखती और डाउनलोड होती है।

Drive मोड में ट्रैश में भेजे गए आइटम, यदि स्वयं स्थायी रूप से न हटाए जाएँ, तो [Google Drive की 30 दिन की ट्रैश नीति](https://support.google.com/drive/answer/14933051?hl=hi) के अनुसार 30 दिन बाद स्थायी रूप से हट जाते हैं। OAuth रहित `local` मोड में 30 दिन पूरे कर चुके आइटम अगली बार ट्रैश देखने पर ShareDesk स्थायी रूप से हटा देता है।

आमंत्रित व्यक्ति नया ShareDesk इंस्टॉल नहीं करता, बल्कि होस्ट द्वारा पहले से बनाए साझा फ़ाइल स्पेस में शामिल होता है।

## 8. काम करने की पुष्टि के बाद प्रोडक्शन सुरक्षा

ऊपर के चरण 7 में साइन-इन, फ़ाइल सहेजना और वास्तव में एक व्यक्ति को आमंत्रित करना जाँच लेने के बाद आमंत्रण कोड जमा करने के अनुरोध को सुरक्षित करें। Firewall सेटिंग ShareDesk को चलाने वाला इंस्टॉल चरण नहीं, बल्कि प्रोडक्शन सुरक्षा का चरण है।

Vercel प्रोजेक्ट के Firewall में नीचे दिया Rate Limit नियम बनाकर `Publish` करें।

यदि पहले से कोई Rate Limit नियम है, तो पहले उसकी शर्तें और उद्देश्य जाँच लें। दूसरे नियम को ऊपर से न लिखें — देखें कि नया नियम जोड़ा जा सकता है या नहीं।

- शर्त: `Request Path` equals `/api/invitations/code`
- शर्त: `Method` equals `POST`
- शर्त: Cookie `sharedesk_session` exists
- कार्रवाई: `Rate Limit`
- तरीका: `Fixed Window`
- आधार: `IP`
- सीमा: `60 सेकंड` में `10 बार`, इससे अधिक पर `429`

तीनों शर्तें डालने पर ही सीमा केवल आमंत्रण कोड जमा करने पर लगती है। नियम बनाते समय Vercel द्वारा दिखाई जाने वाली उपयोग-मात्रा और शुल्क संबंधी जानकारी भी देख लें। सेटिंग स्क्रीन के लिए [Vercel WAF Rate Limiting गाइड](https://vercel.com/docs/vercel-firewall/vercel-waf/rate-limiting) देखी जा सकती है।

## लोगों को आमंत्रित करना और प्रबंधन

1. होस्ट प्रोडक्शन पते का `/admin` खोलता है।
2. आमंत्रण कोड की वैधता अवधि `1 घंटा`, `24 घंटे`, `7 दिन`, `30 दिन` में से चुनें।
3. उपयोग प्रकार `एकल-उपयोग` या `समाप्ति तक असीमित` चुनें।
4. जुड़ने वाले की शुरुआती भूमिका `संपादित कर सकते हैं` (डिफ़ॉल्ट), `अपलोड कर सकते हैं`, `केवल देखना` में से चुनें।
5. बनाया गया कोड और प्रोडक्शन पता प्रतिभागी को भेजें।
6. प्रतिभागी अपने Google खाते से साइन इन करके कोड दर्ज करता है। जुड़ने वाला व्यक्ति उसी भूमिका से शुरू करता है जो कोड में चुनी गई थी।

आमंत्रण कोड पहले से किसी विशेष ईमेल से बँधा नहीं होता। नाम और ईमेल उसी व्यक्ति के Google साइन-इन से लिए जाते हैं जिसने वास्तव में कोड दर्ज किया।

- **एकल-उपयोग:** एक व्यक्ति के सफलतापूर्वक जुड़ते ही यह तुरंत समाप्त हो जाता है।
- **समाप्ति तक असीमित:** समाप्त होने या होस्ट द्वारा निष्क्रिय किए जाने तक कई लोग इसे साथ उपयोग कर सकते हैं।

| अपलोड कर सकते हैं | अपलोड, डाउनलोड, नया फ़ोल्डर बनाना, आइकन की जगह बदलना |
| केवल देखना | केवल देखना और डाउनलोड करना |

भूमिका ऐसा मान नहीं है जो जुड़ते समय एक बार तय होकर वहीं समाप्त हो जाए। `/admin` की उपयोगकर्ता तालिका के भूमिका कॉलम से इसे कभी भी बदला जा सकता है।

व्यवस्थापक स्क्रीन में उपयोगकर्ता को अवरुद्ध किया जा सकता है या दोबारा प्रतीक्षा स्थिति में भेजा जा सकता है, और किसी विशेष डिवाइस का सत्र या उस उपयोगकर्ता के सभी सत्र समाप्त किए जा सकते हैं। यदि आपने `ADMIN_EMAILS` बदला है, तो Vercel के एनवायरनमेंट वेरिएबल ठीक करने के बाद दोबारा डिप्लॉय करना होगा।

## इंस्टॉल के बाद अपडेट

ShareDesk नया संस्करण अपने आप लागू नहीं करता। नया संस्करण मिलने पर व्यवस्थापक के टास्कबार में `अपडेट` पर तारा दिखता है। बटन दबाने पर ShareDesk पहले उसी के भीतर वर्तमान और नवीनतम संस्करण दिखाता है। जिन इंस्टॉल में Vercel पर `SHAREDESK_GITHUB_TOKEN` डाला गया है, वहाँ व्यवस्थापक द्वारा `अभी अपडेट करें` दबाते ही ऐप के भीतर से अपडेट शुरू हो जाता है और प्रगति दिखती है। टोकन रहित इंस्टॉल में पहले की तरह GitHub Actions पेज खुलता है, जहाँ `Run workflow` दबाकर शुरुआत की जाती है। दोनों ही स्थितियों में कमिट `main` में तभी होता है जब जाँचें पास हों, और जुड़ा हुआ Vercel दोबारा डिप्लॉय करता है।

Drive की फ़ाइलें व साझा स्थिति, `.env.local` और Vercel के एनवायरनमेंट वेरिएबल कोड अपडेट में शामिल नहीं होते। अपडेट सुविधा आने से पहले बने इंस्टॉल के एक बार के माइग्रेशन और टकराव-समाधान के लिए [ShareDesk अपडेट](./UPDATE.hi.md) का पालन करें।

## Google Drive से सीधे साझा करना

व्यवस्थापक किसी फ़ाइल या फ़ोल्डर पर राइट-क्लिक करके **Google Drive से साझा करें** दबाए, तो स्वीकृत उपयोगकर्ताओं को देखने या संपादित करने की अनुमति दी जा सकती है। यह सुविधा ShareDesk के भीतर आइटम छिपाने या दिखाने की नहीं है — यह वास्तविक Drive अनुमति है, जो प्राप्तकर्ता के Google Drive के `मेरे साथ साझा किया गया` में भी दिखाई देती है।

फ़ोल्डर की अनुमतियाँ Google Drive के नियमों के अनुसार भीतर के आइटम तक पहुँचती हैं। प्राप्तकर्ता के `मेरे साथ साझा किया गया` में दिखने और देखने बनाम संपादित करने की अनुमति के अंतर की पुष्टि किसी अलग Google खाते से स्वयं करें। स्वचालित जाँच का तरीका [लोकल उपयोग दस्तावेज़ की वास्तविक Drive जाँच](./LOCAL.hi.md#वास्तविक-drive-जाँच) में देखें।

## समस्या समाधान

| लक्षण | क्या जाँचें |
|---|---|
| `redirect_uri_mismatch` | त्रुटि में दिखाए गए `redirect_uri` की तुलना Google Auth Platform के उसी Client ID के `Authorized redirect URIs` से अक्षर-दर-अक्षर करें। यह JavaScript origins नहीं है। |
| `ऐप तक पहुँच नहीं मिल सकती` | जाँचें कि Audience `External` है। यदि Testing बनाए रखना है, तो साइन-इन खाते को Test user में जोड़ना होगा। |
| `org_internal` | यह तब होता है जब Internal ऐप में संगठन के बाहर के खाते से साइन इन किया जाए। इसे External में बदलें या संगठन का खाता उपयोग करें। |
| सहमति के बाद `127.0.0.1` कनेक्शन विफल | setup में यह सामान्य है। एड्रेस बार का पूरा पता कॉपी करके `npm run setup:finish` के प्रश्न में चिपकाएँ। |
| `refresh_token प्राप्त नहीं हुआ` | पहले मौजूदा कनेक्शन और Audience की स्थिति जाँचें। नया टोकन वास्तव में आवश्यक हो और मौजूदा कनेक्शन के कारण जारी न हो रहा हो, केवल तभी [Google खाते के जुड़े हुए ऐप](https://myaccount.google.com/permissions) में जाकर अनुमति हटाएँ और setup दोबारा करें। |
| लगभग 7 दिन बाद Drive कनेक्शन टूट जाना | पहले जाँचें कि Audience `Testing` तो नहीं था। यदि होस्ट टोकन Testing में मिला था, तो In production में बदलकर setup दोबारा करें। पहले से In production हो तो टोकन रद्द करने से पहले वास्तविक प्रमाणीकरण त्रुटि जाँचें। |
| Drive API का 403 लौटाना | जाँचें कि जिस Cloud प्रोजेक्ट में OAuth क्लाइंट बनाया था, उसी में Google Drive API चालू है। यह भी देखें कि Workspace की प्रबंधन नीति बाहरी ऐप रोक तो नहीं रही। |
| केवल Vercel पर साइन-इन विफल | Production एनवायरनमेंट वेरिएबल, स्थिर प्रोडक्शन origin, Google में प्रोडक्शन redirect URI, और एनवायरनमेंट वेरिएबल बदलने के बाद पुनः डिप्लॉय — ये सब जाँचें। |
| आमंत्रण कोड अस्वीकृत होना | `/admin` में कोड की समाप्ति तिथि, सक्रिय स्थिति और उपयोग प्रकार जाँचें। एकल-उपयोग कोड किसी और के पहले सफल जुड़ाव के बाद पहले ही समाप्त हो चुका हो सकता है। |
| केवल कुछ Workspace खातों का विफल होना | संगठन के व्यवस्थापक द्वारा लगाई थर्ड-पार्टी ऐप एक्सेस सीमा या Google Advanced Protection नीति जाँचें। |
| व्यवस्थापक साइन-इन का आमंत्रण माँगना | जाँचें कि साइन-इन ईमेल `ADMIN_EMAILS` से बिलकुल मेल खाता है, और मान बदला हो तो दोबारा डिप्लॉय करें। |
| setup का यह कहकर रुकना कि एक ही नाम की कई स्थिति फ़ाइलें हैं | Drive के `ShareDesk/.sharedesk/` में वह JSON फ़ाइल देखें, सामग्री की तुलना करके रखने योग्य केवल एक छोड़ें, फिर दोबारा चलाएँ। |

### क्या setup दोबारा चलाया जा सकता है?

यदि मौजूदा `DRIVE_ROOT_FOLDER_ID` और स्थिति फ़ोल्डर की ID `.env.local` में हैं, तो setup उसी फ़ोल्डर और मौजूदा स्थिति फ़ाइलों को आगे उपयोग करता है। एक ही नाम की कई मुख्य स्थिति फ़ाइलें होने पर वह मनमाने ढंग से कोई एक नहीं चुनता, बल्कि रुक जाता है — इसलिए Drive में सामग्री जाँचकर केवल एक ही रखनी होगी।

Client secret बदला हो या refresh token दोबारा लेना हो, तो पहले `.env.local` के Client ID और secret नए करें और फिर setup दोबारा शुरू करें। जो कनेक्शन पहले से ठीक चल रहा है, उसे अनुमान के आधार पर रद्द न करें।

## संग्रहण संरचना और सीमाएँ

- ShareDesk का दायरा setup में तय किए गए Drive रूट फ़ोल्डर के भीतर तक है। होस्ट यदि Drive वेब से किसी आइटम को रूट के बाहर ले जाए, तो ShareDesk उस तक नहीं पहुँच पाता।
- एक ही फ़ोल्डर में एक ही नाम का आइटम बनाने या नाम बदलने का काम अस्वीकार कर दिया जाता है।
- HTML, SVG जैसी स्क्रिप्ट चला सकने वाली फ़ाइलें ब्राउज़र में सीधे नहीं दिखाई जातीं, बल्कि डाउनलोड की जाती हैं।
- Google डॉक्स, शीट्स, स्लाइड्स और ड्रॉइंग्स को PDF में बदलकर पूर्वावलोकन किया जाता है।
- मुफ़्त Google Drive की जगह और ट्रैश में रखने की अवधि होस्ट खाते की Google नीति के अनुसार होती है।

Drive मोड में `ShareDesk/.sharedesk/` में उपयोगकर्ता व आमंत्रण, इस समय जुड़े हुए लोग, Drive साझा अनुमतियाँ, फ़ोल्डर नोट और आइकन की जगह सहेजी जाती है। सामान्य फ़ाइल सूची में यह फ़ोल्डर छिपा रहता है। एक ही स्थिति एक साथ बदलने पर पहले सहेजा गया परिणाम बना रहता है और देर से आया अनुरोध टकराव के साथ समाप्त होकर नवीनतम स्थिति दोबारा पढ़वाता है।

कोडिंग AI के साथ इंस्टॉल करना हो तो [AI इंस्टॉल गाइड](./AI_INSTALL.hi.md) उपयोग करें। डेवलपमेंट व जाँच कमांड और एनवायरनमेंट वेरिएबल की पूरी तालिका [लोकल निजी उपयोग](./LOCAL.hi.md#डेवलपर-संदर्भ) में अलग से दी गई है।
