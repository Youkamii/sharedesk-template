# 멀티 데스크 인수인계

작성 2026-08-25. 다음 세션이 이 문서만 읽고 이어받을 수 있게 쓴다.

## 지금 무엇을 만들고 있나

한 설치 주소 안에 데스크(스페이스)를 여러 개 두는 기능이다. URL 첫 세그먼트로 가른다.

```
https://<주소>/A/files     → A 스페이스
https://<주소>/sea/files   → sea 스페이스
```

관련 이슈: #12 멀티 데스크, #13 닉네임, #10 공개 폴더, #11 사이드바.

## 확정된 요구사항 (사용자 지시)

### 멀티 데스크 (#12)
- 스페이스는 **관리자만** 만들고 관리한다. 멀티데스크 관리 창이 따로 있다
- 일반 유저는 **초대받은 스페이스만** 접속. 초대 없으면 주소를 알아도 거부
- 관리자는 로그인하면 **자기 스페이스 목록**부터 본다. 일반 유저도 여러 곳이면 목록, 한 곳이면 바로 입장
- **나가기 버튼은 갈 곳이 둘 이상일 때만** 보인다. 역할이 아니라 목적지 유무 기준
- 스페이스마다 사용자 명단·역할·용량 제한·채팅·공유 링크·아이콘 배치가 전부 분리된다
- 가입은 기본 데스크에서만(기존 초대 코드). 스페이스 멤버십은 관리자가 가입자를 명단에 추가
- 스페이스 삭제는 등록 해제만 — 파일은 남긴다

### 닉네임 (#13)
- 입장할 때 닉네임을 받고, 접속 인원 표시와 우측 하단 이름이 닉네임으로 보인다
- 관리자 화면에는 구글 이름도 함께, 닉 변경 기록도 보인다
- 자기 이름을 클릭하면 변경
- 허용 문자: 한글·영어·숫자와 `- . ( ) @ ~ # ^ &` — 슬래시 제외

### 공개 폴더 (#10) — 완료 (아래 3-4)
- 외부인이 로그인 없이 주소로 들어와 받고 올린다
- 화면은 폴더 목록이 아니라 **바탕화면과 똑같이**. 좌측 상단에 `공개폴더: {이름}`
- 나가기 버튼은 데스크 멤버에게만
- **하위 폴더는 아무도 못 만든다**(멤버 포함). 평평하게 유지
- 폴더별 총 용량·파일 크기·개수 상한, 공개 시작·종료 시각
- 접근 권한은 역할 최소선 + 개인 지정 **둘 다**, OR 판정
- 설정 화면에 공개 폴더별 파일 목록·관리 페이지

### 사이드바 (#11) — 완료 (아래 3-5)
- 우측 여백에 손잡이를 눌러 여는 사이드바
- 추가기능(＋) 버튼 삭제, 상단엔 다운로드 우선만 남김
- 사이드바로 이동: 간이 링크 만들기, 생성된 링크, 다른 데스크에서 받기, 공개 폴더 입장
- 생성된 링크에 권한 — 일반 유저는 자기 것만, 관리자는 전부

### 핵심 설계 결정

**스페이스 컨테이너는 `.spaces/<slug>`.** 점 접두사라 기존 데스크 목록에 안 뜬다. 기존 단일 데스크는 `folderId: null`로 설치 루트 그 자체를 쓴다 — 그래서 **마이그레이션 스크립트가 없다.** 1.0.0을 받아도 파일이 한 개도 안 움직이고 기존 주소가 그대로 동작한다.

**정체·세션 유효성은 기본 데스크가 단일 진실 원천이다.** 스페이스 명단에서는 멤버십과 역할만 읽는다. 스페이스 명단의 세션 필드로 판정하면 기본에서 철회한 토큰이 스페이스에서 계속 살거나, 새 토큰이 옛 레코드와 어긋나 거부된다. 같은 사람이 스페이스마다 다른 역할을 가질 수 있다.

**주의: `folderId`의 의미가 어댑터마다 다르다.** local은 루트 기준 상대경로, drive는 폴더 id다.

### 0. 문맥 전달 방식 재설계 — 완료 (2026-08-26)

`enterWith`(`enterSpace`)를 완전히 제거했다. 문맥은 `AsyncLocalStorage.run()` 기반
`runWithSpace` 하나로만 세워진다.

- **러너 4종** (`src/lib/api.ts`): `runWithSession(options, body)` /
  `runWithUploadRights` / `runWithEditRights` / `runWithAdmin`.
  라우트는 `export async function GET(req) { return runWithSession(null, async ({ session, space }) => {...}); }`
  형태로 본문 전체를 러너에 넘긴다. 러너가 헤더의 스페이스를 등록부와 대조(미등록 404)
  → `resolveSpaceSession`으로 세션 판정(미인증 401 / 비멤버 403) → 본문을
  `runWithSpace(스페이스)`로 감싸 돌린다. run()이 끝나면 문맥이 복원되므로 요청
  사이에 새지 않는다. 기존 `requireSession` 계열과 `establishSpaceContext`는 삭제.
- **판정 순수화**: `resolveSpaceSession(token, space, options)`가 명시 인자만 받고
  주변 ALS·next/headers를 안 읽는다. `tests/space-membership.test.ts`가 이제 실제
  함수를 직접 돌린다(전에는 판정 순서를 재현만 했다). 경계 테스트(문맥이 run 블록
  밖으로 안 샘, enterWith 호출 금지 소스 검사)도 추가.
- **공개 라우트 6개**(`api/auth/*` 3, `api/share/[linkId]`, `api/invitations/code`,
  `api/update-policy`)는 본문을 `runWithSpace(null, ...)`로 감싸 기본 문맥을 명시.
  cron(`api/cron/share-cleanup`)은 예약 실행이면 기본 문맥, 수동이면 `runWithAdmin`.
- **`after()` 문맥 보존 확인됨**: Next 16.3의 `after()`는 콜백을
  `AsyncLocalStorage.bind`(전체 ALS 스냅샷)로 감싼다
  (`node_modules/next/dist/server/after/after-context.js`의 `bindSnapshot`).
  `recordActivityAfter`가 응답 뒤에 돌아도 스페이스 문맥을 유지한다 — 스모크에서
  스페이스 업로드 기록이 스페이스 activity.json에 정확히 남는 것을 실측 확인.
- **런타임 스모크 18항목 통과**: 로컬 드라이버 + `next start`로 실서버를 띄우고

  격리, 번갈아 6회·동시 20요청 문맥 오염 없음, 비 matcher 라우트(chat·presence)
  분리, 기본 목록의 `.spaces` 미노출을 확인했다.
- 부수 정리: 죽은 코드 `getSession` 삭제, `drive/move`의 리터럴 제어문자 정규식을

### 1. 클라이언트 배선 — 완료 (2026-08-26)

헤더 대신 **경로 프리픽스**로 확정했다: 스페이스 화면의 API 호출은
`/sea/api/...` 로 나가고, proxy가 `/api/...` 로 rewrite하며 스페이스 헤더를
심는다. 헤더 방식은 iframe·anchor.href·window.open(미리보기·다운로드)에 헤더를
실을 수 없어 전 경로를 덮지 못한다 — 프리픽스는 fetch와 URL 내비게이션을 한
메커니즘으로 덮고, 스페이스 요청이 전부 proxy 정규화를 거치게 된다.

- `src/lib/client/api-path.ts` 신설: `apiPath("/api/x")`가 주소창 경로에서
  스페이스를 파생(`matchSpaceRoute` 재사용 — proxy와 같은 판정)해 프리픽스를
  붙인다. 서버 렌더 중(window 없음)에는 그대로.
- 클라이언트 `/api/` 리터럴 77곳 전부 `apiPath(...)`로 감쌈(FilesView 37,
  AdminView 14, 창·다이얼로그 25, transfer.ts 1). apiJson 헬퍼는 그대로 두고
  리터럴 발생 지점에서 감쌌다 — 이중 프리픽스가 원천 차단된다.
- `space-routing.ts`: `/slug/api`도 스페이스 경로로 인정. `proxy.ts`: matcher에
  `/:slug/api/:path*` 추가, 스페이스 api 경로 미인증은 redirect 대신 401 JSON.
- 페이지 게이트: `files/page.tsx`·`admin/page.tsx`가 러너와 같은
  `resolveSpaceSession`으로 판정 — 미등록 스페이스 `notFound()`, 비멤버는
  `/files`로 리다이렉트("주소를 알아도 거부" 요구사항), 스페이스의 비관리자가
  `/sea/admin`에 오면 `/sea/files`로. 로케일·데스크 설정 표시는 기본 데스크
  기준(스페이스 설정 화면이 아직 없다).
- 검증: 전체 340+1 테스트 통과(종료 코드 직접 확인), tsc·eslint 깨끗,
  `next build` 성공. 런타임 스모크 — 0번의 18항목 회귀 통과 + 1번 신규 13항목
  (`/sea/api` 목록·다운로드 내용 일치, 위조 헤더를 프리픽스가 덮음, 미인증
  401 JSON, 미등록 404, 비멤버 페이지 리다이렉트, 관리자/비관리자 admin 게이트,
  기본 데스크 경로 무영향) 통과.
- 주의: 스모크 서버를 TaskStop으로 죽여도 npx의 node 자식이 살아남아 포트를
  쥔다 — 재검증 전에 3777 리스너를 확인하고 죽일 것(한 번 옛 빌드에 대고
  스모크를 돌릴 뻔했다).

### 2. proxy matcher 정리 — 완료 (2026-08-26)

스페이스로 가는 통로를 **경로 프리픽스 하나로 단일화**했다.

- matcher를 `/api/:path*` 전면으로 넓혔다(기존 `/api/drive`·`/api/admin`·
  `/api/spaces` 부분 목록 폐기). 이제 모든 API 요청이 proxy를 지나며,
  클라이언트가 직접 보낸 `SPACE_HEADER`는 어떤 경로에서도 지워진다 — 예전의
  "형태 검증 후 재주입"을 삭제했다. 러너에 도달하는 스페이스 헤더 = proxy가
  프리픽스에서 심은 값, 이것이 불변식이다.
- 공개 API는 서명 사전 검사를 면제받는다: `isPublicApiPath()`
  (space-routing.ts) — `/api/auth*`, `/api/share/<linkId>`,
  `/api/invitations/code`, `/api/update-policy`, `/api/cron/*`. 러너 쪽 공개
  라우트 목록과 정확히 대칭이고, 최종 판정은 언제나 각 라우트가 한다.
- 검증: 전체 341+1 테스트 통과(exit 0), tsc·eslint 깨끗, build 성공. 런타임
  스모크 1부 23항목(직접 헤더가 지워져 기본 데스크로 처리되는 것, 공개 API
  3종의 무세션 접근 포함) + 2부 13항목 통과.
- 주의: 새 API 공개 라우트를 만들면 `isPublicApiPath` 목록에도 넣어야 한다 —
  안 넣으면 matcher 전면 확장 때문에 무세션 호출이 proxy 401로 죽는다.
  (update-flow 테스트가 share 경로의 목록 등재를 검사한다.)

  `public-folders.ts`가 `node:crypto`라 클라가 못 가져오는 구조 탓 — 상수를
  공용 순수 모듈로 빼야 근본 해결. 순수 정리라 결함 커밋과 분리.
- **PublicFolderView가 FilesView 상수(ICON_* 등) 복제**(단순화 minor): 이번에
  겹침 방지 배치는 감쌌으나 상수는 여전히 복제 — `files/ui-scale` 같은 공용
  모듈로 추출 여지. 결합도 낮추는 순수 정리라 분리.

### 4. 나중에 다룰 것

- **스페이스 관리·설정·공유의 완전 지원(red-review에서 UI로만 막아 둔 것)**:
  지금은 스페이스에서 관리 화면·공유 링크·데스크 임포트 UI를 **숨겨** 죽은
  기능을 못 만지게만 했다. 요구사항은 "스페이스마다 공유 링크·명단이
  분리"이므로 최종적으로는 (a) 공유 링크 소비를 스페이스별로(링크에 스페이스
  인코딩), (b) 스페이스별 초대/세션/설정을 스페이스 문맥에서 실제 동작하도록
  지원해야 한다. 그 전까지 UI 숨김이 임시 방어다
- **presence/chat 만료링크 청소 타이머**: `cleanupAfter`가 모듈 전역이라
  청소가 현재 요청의 스페이스 문맥에서만 돌고 10분 창을 전 데스크가 공유
  → 붐비는 데스크가 창을 선점하면 다른 데스크 만료 링크가 밀린다(cron
  스페이스 미순회와 같은 뿌리). 스페이스별 타이머나 cron 순회로 해결

- **무로그인 공개 업로드 가용성(#10)**: 전역 rate cap(60/min)이 XFF 회전
  공격으로 채워지면 정상 방문자 업로드가 창마다 굶는다. 신뢰 프록시 뒤
  실 IP 확정 또는 폴더별 캡으로 보완(디스크 방어인 폴더 상한·예약 4개는 이미

- **스페이스 공유 링크**: 소비 라우트 `/api/share/[linkId]`가 항상 기본 데스크를 본다. 링크에 스페이스가 인코딩돼 있지 않아 구조적으로 스페이스 링크를 못 연다. desk2desk(#7)도 같은 영향을 받는다
- **삭제 후 슬러그 재생성**: 등록만 지우고 폴더·명단이 남아, 같은 슬러그를 다시 만들면 옛 멤버가 approved 그대로 접근을 되찾고 옛 파일이 붙는다

## 작업 방식 (지켜야 할 것)

- 비자명한 구현은 kickoff 절차: 태스크 분해 → 이슈 → 기능별 실행 검증 → 커밋(#이슈) → 푸시 전 적대 리뷰
- **실행한 것만 완료다.** 코드를 읽고 "될 것 같다"로 판정하지 않는다
- 커밋 메시지는 다음 세션이 커밋만 읽고 무엇을·왜 했는지 알 수 있게
- `Co-Authored-By` 트레일러 절대 금지
- 검증 명령: `npm test`, `npx tsc --noEmit`, `npx eslint src/ tests/`, `npm run build`
- 파이프를 거치는 검증은 종료 코드를 따로 확인한다(`| tail`을 쓰면 tail의 코드가 나온다)
- 소스에 리터럴 제어문자를 넣지 않는다. 정규식에 필요하면 유니코드 이스케이프 표기로 쓴다
