# ShareDesk

구글 드라이브 폴더 하나를 **여럿이 함께 쓰는 공유 저장소**로 만들어주는 웹앱.

- 들어오려는 사람은 구글 계정으로 로그인하고, **관리자가 승인해야** 열린다.
- 드라이브에 연결되는 계정은 주인 한 명뿐 (최초 1회 setup). 나머지는 주인의 드라이브 권한을 빌려 쓴다.
- 목록·폴더 이동·업로드(드래그앤드롭)·다운로드·새 폴더·이름변경·삭제(휴지통) 지원.

## 동작 구조

```
사용자 (구글 로그인) → 승인 대기 → 관리자 승인
                                      ↓
        ShareDesk 서버 (세션 확인 → Drive API 대행) → 주인의 드라이브 'ShareDesk' 폴더
```

- OAuth scope는 `drive.file` — 이 앱이 만든 폴더·파일만 접근 가능. 주인 드라이브의 다른 파일은 애초에 보이지 않는다.
- 삭제는 드라이브 휴지통으로 이동 (주인이 복구 가능).
- 대용량 업로드는 서버를 거치지 않고 브라우저 → 구글 직행(resumable) 경로를 쓴다.

## 세션 정책

로그인은 90일 유지되지만 **관리자가 언제든 끊을 수 있다.** 토큰만 믿고 통과시키는 대신
요청마다 승인 상태를 확인하기 때문이다.

| 관리자 동작 | 결과 |
|---|---|
| 차단 | 화면 접근 즉시 차단, 열려 있던 파일 목록도 5초 안에 끊김 |
| 세션 끊기 | 그 사람의 모든 기기에서 로그아웃 (기기 분실 대비). 승인 상태는 유지되어 다시 로그인하면 들어옴 |
| 삭제 | 명단에서 제거. 다시 로그인하면 승인 대기로 새로 등록됨 |

차단·세션 끊기를 하면 기존 로그인은 무효가 되므로, 다시 승인해도 그 사람은 새로 로그인해야 한다.

## 사용자 명단은 어디에 있나

별도 데이터베이스 없이 드라이브 루트 폴더 안 `.sharedesk/users.json`에 저장한다.
이 명단이 곧 접근 권한이므로 파일 기능(목록·다운로드·업로드·이름변경·삭제)에서
**차단**되며, 사용자는 점(.)으로 시작하는 이름을 만들 수도 없다. 주인은 드라이브 웹에서
직접 열어볼 수 있다.

## 최초 설정 (주인 1회)

1. **구글 클라우드 콘솔** (console.cloud.google.com)
   - 새 프로젝트 생성 → "API 및 서비스 → 라이브러리"에서 **Google Drive API 사용 설정**
   - "OAuth 동의 화면": User Type **외부**, 앱 이름 지정 → 만들기 → **앱 게시(프로덕션)** 로 전환
     (테스트 상태로 두면 로그인이 7일마다 만료된다)
   - "사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID" → 유형 **데스크톱 앱**
   - 발급된 **클라이언트 ID / 클라이언트 보안 비밀**을 복사

2. **로컬 설정**
   ```bash
   npm install
   # .env.local 파일에 두 값을 기입:
   #   GOOGLE_CLIENT_ID=...
   #   GOOGLE_CLIENT_SECRET=...
   npm run setup
   ```
   출력된 URL을 브라우저에서 열어 로그인·동의하면, 스크립트가 자동으로:
   - refresh token 획득 → `.env.local` 기록
   - 드라이브에 `ShareDesk` 루트 폴더 생성
   - 로그인한 계정을 **관리자**로 등록 (`ADMIN_EMAILS`)
   - 세션 서명 비밀 생성

3. **로그인 콜백 주소 등록** — 구글 클라우드 콘솔의 같은 OAuth 클라이언트에서
   "승인된 리디렉션 URI"에 아래를 추가한다:
   ```
   http://localhost:3000/api/auth/google/callback
   https://<배포도메인>/api/auth/google/callback
   ```

4. **실행**
   ```bash
   npm run dev   # http://localhost:3000
   ```
   주소를 아는 사람이 구글 로그인을 하면 승인 대기 상태가 되고, 관리자가 `/admin`에서 승인하면 들어온다.

## 환경 변수 (.env.local — 절대 커밋 금지)

| 변수 | 설명 |
|---|---|
| `ADMIN_EMAILS` | 관리자 이메일, 쉼표로 여러 개 (setup이 자동 기입). 관리자 판정의 진실 원천 |
| `ACCESS_KEYS` | 손님용 임시 접속 키 (선택). 비우면 구글 로그인만 사용 |
| `SESSION_SECRET` | 세션 쿠키 서명 비밀 (필수, setup이 생성). 없으면 로그인 자체가 거부된다 |
| `PUBLIC_BASE_URL` | 배포 주소. 비우면 요청 origin으로 콜백 URL을 만든다 |
| `STORAGE_DRIVER` | `drive` 또는 `local`(개발용 로컬 폴더) |
| `LOCAL_STORAGE_ROOT` | local 드라이버가 쓸 폴더 (기본 `.devstorage`) |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | OAuth 클라이언트 (데스크톱 앱 유형) |
| `GOOGLE_REFRESH_TOKEN` | setup이 획득 |
| `DRIVE_ROOT_FOLDER_ID` | setup이 생성한 루트 폴더 ID |

## 배포 (Vercel)

1. 이 repo를 Vercel에 연결
2. 위 환경 변수 전부를 Vercel 프로젝트 환경 변수로 등록 (`STORAGE_DRIVER=drive`, `PUBLIC_BASE_URL=https://도메인`)
3. 구글 OAuth 클라이언트에 `https://<도메인>/api/auth/google/callback`을 리디렉션 URI로 추가
4. 배포 주소를 공유하면 각자 구글 로그인 → 관리자가 승인

## 개발 모드

자격증명 없이 UI를 만지려면 `.env.local`에 `STORAGE_DRIVER=local`만 두면 된다.
`.devstorage/` 폴더가 가짜 드라이브 역할을 한다.

## 알아둘 것

- 관리자 판정은 `ADMIN_EMAILS` 환경변수가 진실 원천이다. 명단 파일(`users.json`)이 어떤 이유로 바뀌어도 권한이 따라 올라가지 않는다.
- 손님용 키(`ACCESS_KEYS`)를 쓴다면, 회수는 그 키를 빼고 재배포/재시작하면 된다 — 그 키로 만든 기존 세션도 함께 무효가 된다. 키 추측 시도는 IP당 분당 10회로 제한된다.
- 앱이 만지는 범위는 setup이 만든 루트 폴더 **안쪽으로 한정**된다. 주인이 파일을 드라이브에서 폴더 밖으로 옮기면 앱에서 더는 접근되지 않는다.
- 같은 폴더에 같은 이름이 있으면 덮어쓰지 않고 거부한다(업로드·이름변경·새 폴더 공통).
- 무료 드라이브 용량은 15GB (주인 계정 기준).
- 구글 문서·시트 등 구글 네이티브 형식은 다운로드 미지원 (일반 파일만).
